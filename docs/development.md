# Development

Run `pip install -e ".[test]"`, then `pytest`. Frontend: `cd web`, `npm ci`, `npm run build`. Start the backend with `mediaguard`; for Vite development, run `npm run dev` in `web/` and keep the backend on port 8765.

`config.json` is a local file with `discord.enabled`, `discord.max_attachment_bytes`, `operator.host`, and `operator.port`. The host must be loopback. The attachment limit defaults to 25 MiB and accepts values from 1 byte to 100 MiB; only the first 4 KiB are read for a signature. `secrets.env` or the `DISCORD_BOT_TOKEN` environment variable may supply MediaGuard's own token. Missing token leaves Discord unconfigured while the dashboard still works. The bot needs Guilds, Guild Messages, and privileged Message Content intents; enable Message Content Intent in its Discord application settings or ordinary guild attachment fields may be empty. SQLite is created at `runtime/mediaguard.sqlite3`; inspection data is not written there.

Tests inject a fake Discord client and attachment downloader and never connect to Discord. Do not use production tokens or databases in tests. Build and test before enabling a real connection. The bot observes new guild messages but does not moderate them. A forward is identified by Discord's forward reference type and inspected only through exposed snapshots. Missing snapshot metadata and uninspected forward embeds produce `UNAVAILABLE`; links and message text are not fetched. The inspector returns `SAFE`, `MATCH`, or `UNAVAILABLE`, with `UNAVAILABLE` never interpreted as safe.
