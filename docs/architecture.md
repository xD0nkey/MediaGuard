# Architecture

`Runtime` owns startup, configuration, the SQLite database, and the Discord service. `DiscordService` owns one `discord.py` client and its event loop. It ignores the bot's own messages and DMs, filters protected channel IDs, and asks `attachments.py` to inspect direct and forwarded snapshot attachments. `embed_phrases.py` checks configured phrases against ordinary and forwarded-snapshot embed text. Neither inspector has moderation side effects.

For a confirmed `MATCH`, the service reserves one durable audit row keyed by Discord message ID before attempting deletion. It checks View Channel and Manage Messages, calls Discord delete once, and records the outcome. A returned delete call records a UTC `deleted_at`; an exception records `failed_or_unknown` and is never presented as a successful block. A duplicate delivery or process restart cannot blindly retry the same deletion. `SAFE` causes no action. `UNAVAILABLE` causes no deletion and writes a sanitized Activity code.

Detection notifications are independent of deletion. When enabled, MediaGuard checks View Channel and Send Messages in the configured Detection channel and sends one red embed only after deletion succeeds. `detection_notice.py` renders already-established facts for audio or blocked embed phrases. It includes the source user's display name and stable ID, source channel, detected audio type or configured rule name, source type, actual action, and confirmed deletion time. It contains no emoji, message body, source embed text or URL, attachment URL, download link, or media bytes. Failed delivery is recorded separately from successful deletion.

SQLite stores the original guild, channel, message, and author IDs; available display names; detection kind and source; audio type and filename when available; stable rule ID and short configured rule name for embed matches; detection time; configured delete action; deletion outcome and successful deletion time; and notification outcome. It stores no full body, source embed text, attachment bytes, URL, temporary media path, warning, strike, reputation, or case. Enforcement rows older than the configured retention period are pruned at startup. Separate tables store per-guild protection settings and blocked embed phrase rules.

The local FastAPI API exposes status, activity, guild inventory, protection settings, blocked phrase rules, and recent detection metadata to the React dashboard. The inventory is read from the existing Discord client cache on its event loop, without a second connection or API polling. Protection and rule mutations require explicit action headers and validate guild scope against that inventory. Saved protection settings override ignored `config.json` defaults for the relevant guild. API access is loopback only with Host and Origin checks.

The client requests Guilds, Guild Messages, and privileged Message Content intents. Message Content is needed because Discord otherwise withholds attachment fields from ordinary guild messages. The bot needs View Channel and Manage Messages where it enforces, plus View Channel and Send Messages in the Detection channel when notifications are enabled. It does not request Administrator, Members, or Presences. Discord permission checks are still followed by handling API failure because permissions can change between the check and call.

Audio inspection checks at most 4 KiB from an eligible Discord attachment CDN URL with no redirects and an eight-second timeout. It recognizes MP3 Layer III frames, RIFF/WAVE, native FLAC, Ogg Opus, Ogg Vorbis, and ISO BMFF with an `M4A ` brand. A generic `ftyp` box, incomplete download, size limit, unresolved media hint, or missing forwarded metadata is `UNAVAILABLE`. `SAFE` means no supported media evidence was found within this configured inspection boundary. Embed inspection reads only bounded title, description, and field-value text; it makes no HTTP request. Rules are checked by creation time then ID. Confirmed audio matches take precedence when both paths match, and both use the same message-ID reservation and delete path. Message edits are not inspected. MediaGuard does not crawl external-service links.
